子项以如下锚点评分：

| 完成度 | 建议分值 |
| --- | ---: |
| 基本忠实，只存在少量抗锯齿、字形或微小阴影差异 | 子项满分的 90–100% |
| 可明确对应原图，存在一些位置、形状、色彩偏差 | 65–85% |
| 元素大致存在，但明显简化，密度或比例偏离 | 35–60% |
| 只有抽象概念相似，缺失关键元素 | 5–30% |
| 未做或与要求相反 | 0% |

这是人工评分锚点，不是算法相似度。每个子项注明可观察的原因，例如“按钮全有但 ABXY 布局偏小”，不要只写“感觉一般”。不要因为截图低分辨率导致的原图不清晰强行扣所有候选的分。

## 无效运行与故障分类

- 修改 Prompt／参考图／评分脚本、读取其他候选答案、使用现成复刻代码，或把整屏／整机截图贴上去盖透明按钮：记为 `invalid`，总分 `null`，保留原因与证据，不与有效实现排序。
- 没有实现、构建失败、交互缺失：这些是候选结果，不自动归为基础设施失败。可保留视觉证据逐项打分，未完成项为 0，写明实际可运行性。
- 相同环境中已证实的依赖服务故障、浏览器无法启动、题目图片未提供等：记为 `infrastructure_failure`，修好后重跑，不伪造 0 分或 100 分。
- 测试标记缺失但画面存在：记录自动化不完整，进行人工检查；不能单因缺少标记就把视觉 80 分归零。若符合题目的真实功能，可给对应功能分，并在交付项说明标记遗漏。

总分是六个大项的和。汇报同时保留视觉 `/80`，避免一台“能点但不像”的 3DS 被解读为视觉复刻优秀。
